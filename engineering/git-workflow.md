# Git Workflow and Pull Requests

> **Purpose:** Preserve a clear, reviewable history of engineering decisions.
>
> **Pravaah OS:** v1.0.0  
> **Last Updated:** 2026-08-08  
> **Owner:** Technology Lead  
> **Related Documents:** [Delivery](delivery.md), [Decision Records](../decisions/README.md)  
> **Estimated Reading Time:** 3 minutes

Use short-lived, purpose-named branches. Keep commits focused on one coherent change and write messages that state the outcome, not just the file touched.

Every pull request states the problem, approach, validation performed, risks, and follow-up work. Link the relevant issue or ADR where one exists. Do not merge a change that is not understood by its author and reviewer.

Protected branch and CI settings will be established when Product 001 implementation is approved.
